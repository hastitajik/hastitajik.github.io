01 · M.Sc. research, in progress

Evidence certificates for Graph-R1

Can a multi-hop QA system say why it trusts an answer, and be right when it does?

Extends Graph-R1: knowledge-hypergraph retrieval-augmented generation trained with reinforcement learning
github.com/hastitajik/Graph-R1-v1 ↗

Graph-R1 learns to query a knowledge hypergraph and decide when it has seen enough, but its answers come with no evidence, so a lucky guess looks the same as a documented fact. I added a training-free layer on top of it. A frozen LLM breaks each question into facts that must be proven. A value-of-information controller then chooses the next retrieval action (fill a missing fact, follow a chain, find a second source, challenge with counter-evidence, re-verify a source) and stops when no action is worth its cost. An answer gets a certificate only when every fact has a source, the sources are independent, and no contradiction remains.

2WikiMultiHopQA · 100 held-out test questions · frozen LLM
67certified
33uncertified
85%exact match among certified answers
18%exact match among uncertified answers
  • Overall exact match did not improve on a no-RL Graph-R1 baseline (0.63 vs 0.70, not statistically significant, McNemar p = 0.14). The value of the method is in separating trustworthy answers from the rest, not in raw accuracy.
  • Evaluation: the baseline, the full controller and 11 ablations on the same questions, with 95% confidence intervals and paired McNemar tests. Source verification was the only component whose removal had a visible effect. Learning action success rates cut searches per question by 22% at equal accuracy.
  • 125 automated tests. An independent review found cases where a certificate was issued for a wrong answer, and those were fixed.

Next: fix the remaining wrong-but-certified answers (mostly location and date-of-death questions), run on all 128 test questions with the final model, and extend to HotpotQA and MuSiQue.

02 · Applied computer vision

Broiler health early-warning system

Overhead cameras in a broiler house, read every five minutes, compared with what is normal for this flock at this age and this hour.

Built on Multi-camera detection and tracking for individual broiler monitoring
Cardoen et al., Computers and Electronics in Agriculture, 2025 (MVBroTrack)
github.com/hastitajik/broiler-health-early-warning ↗

The system processes the 5-minute clips recorded by the farm's DVR and extracts four flock-health signals. Each signal is compared with a baseline (median and MAD) for the same flock age and hour of day, and rule-based alerts fire when a signal stays out of range. A web panel shows farmers and the veterinarian where to look first. It does not replace a veterinary examination.

  • Two detection modes: colour segmentation that needs no training, and a YOLO detector fine-tuned on the farm's own frames with floor-plane tracking (Hungarian matching, in metres).
  • Camera calibration by homography onto a floor map with feeder, drinker, wall and corner zones; dated versions for when a camera moves.
  • Validation against the vet log: recall, precision, false alerts per week and warning time.
  • FastAPI panel, SQLite storage, webhook notifications, and 40 pytest tests on synthetic video.

Alert thresholds still need tuning with the farm veterinarian on real flock data, so there are no field accuracy numbers yet.

FCLCNN-LSTM for telecom churn risk

fclcnn-lstm-churn ↗
Risk assessment of customer churn in telco using FCLCNN-LSTM model
Wang et al., Expert Systems with Applications, 2024

A fully connected layer homogenises customer features, a 2D CNN extracts spatial patterns from the reshaped vector, and an LSTM extracts sequential ones. Built in TensorFlow on the IBM Telco dataset (7,043 customers, 26.5% churn) with Maj-LASSO feature selection for imbalanced data (30 → 22 features) and hyperparameters searched with the Whale Optimization Algorithm.

TEP: Transformer anomaly detection for multivariate time series

tep-anomaly-detection ↗
Pre-training Enhanced Transformer for multivariate time series anomaly detection
Wang et al., Information Fusion, 2025

A two-stage unsupervised framework in PyTorch: a CANets encoder (temporal convolution plus multi-head attention) is pre-trained and frozen, a reconstruction Transformer is trained on its features, and an anomaly-feature-knowledge score is thresholded automatically with Peaks-Over-Threshold. Normalisation, windows and thresholds are computed per entity so data never leaks between machines.

  • Runs on the SMD, MSL and PSM benchmarks and reproduces the paper's ablation, kernel visualisation, parameter-sensitivity, noise-robustness and knowledge-transfer studies.
  • All hyperparameters in one config object; every ambiguity in the paper marked PAPER GAP in the code; smoke tests for each module.

The published outputs come from a two-epoch check run. AUC is about 0.84 on SMD and 0.86 on PSM, but F1 is still low at that budget, so these numbers are not comparable to the paper's.

Friend recommendation with link prediction, clustering and a genetic algorithm

social-network-recommender ↗
A recommender system for social networks using link prediction, clustering and genetic algorithm
Lu et al., Egyptian Informatics Journal, 2025

Edge weights mix cosine similarity of user profiles and of connection vectors. Communities come from a minimum spanning tree whose heaviest edges are cut, then merged greedily while modularity rises. Inside each community, loop-free paths of length 2 to L score candidate friends, and a genetic algorithm tunes the number of clusters and the path length.

  • Single-file Python and NetworkX, 10-fold cross-validation over edges.
  • Tested on a synthetic 400-user network with built-in community structure (the paper's Pokec data is not bundled): recall@10 of 0.17, with precision limited because each test user has only one or two held-out links.
